Opencode integration

Let your agents read what you've written

knowledge-engine exposes your vault to Opencode as a search_vault tool. Agents call it on demand and ground their answers in your notes, instead of relying on memory files you update by hand.

In action: an agent calls search_vault against an indexed vault and grounds its answer in your notes.

The only install path: clone the repo

At the moment knowledge-engine is designed to be run locally rather than installed through a package registry like npm. To get started, you can clone the repository, build it from source, and point it directly at your local vault.

Setup

Four steps, one time. After that the MCP server stays registered and agents can query your vault from any session.

  1. Clone and build

    Clone the repository and compile the TypeScript. The MCP server runs from the compiled output.

    # git is the only distribution channel
    git clone https://github.com/sodrooome/knowledge-engine.git
    cd knowledge-engine
    npm install
    npm run build

  2. Configure and index your vault

    Copy .env.example to .env and set EMBEDDING_API_KEY, LANCEDB_PATH and NODE_ENV. Then index the vault so there is something to search.

    # configure once: EMBEDDING_API_KEY, LANCEDB_PATH, NODE_ENV
    cp .env.example .env

    # index a vault (skips .obsidian, .trash)
    npm run index -- ~/path/to/vault

  3. Register the MCP server

    Add a knowledge-engine entry to the mcp block of your opencode config. The entry is identical in both scopes; only the file location differs. Replace <repo-path> with the absolute path to the cloned repository.

    "knowledge-engine": {
      "type": "local",
      "command": [
        "node",
        "--env-file=<repo-path>/.env",
        "<repo-path>/dist/mcp-server.js"
      ],
      "enabled": true
    }

  4. Restart Opencode

    Config is loaded once at startup, so quit and restart Opencode for the server to appear.

Project scope or global scope

You can register the server in either scope, or both (opencode merges configs and duplicate keys are idempotent).

Project scope (recommended default). Add the entry to the cloned repo's opencode.json (next to any other project servers). The tool is then available whenever you work in that project.
Global scope. Add the entry to ~/.config/opencode/opencode.json instead. The tool is available from every project on the machine, so your personal knowledge base is queryable from any codebase.

Using it

There is nothing to invoke manually. In any session with the server registered, just ask a question that your notes might answer, for example "what do I know about eventual consistency?". The agent calls search_vault, reads the ranked citations, and answers using that context.

Index freshness. search_vault only searches what has been indexed. After adding or editing notes, re-run npm run index -- ~/path/to/vault so the tool reflects your latest writing.
